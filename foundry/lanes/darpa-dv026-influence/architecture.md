# Architecture — DARPA DV026 Influence Benchmarks

Status: executable public reference workload, with measured trials generated by the shared runner.

## Purpose and implemented method

Make allocation, agent decisions and sensitivity to information independently inspectable before introducing model-controlled behavior.

The market module clears unit-demand bids across multiple assets and rounds. It freezes seeded valuation adjustments, information sensitivity and bid shading once, then uses the same agents for factual news and the no-news counterfactual. Stable price/identity ordering resolves ties. Allocation value is compared with the feasible highest-value allocation at the same supply.

## Data and control flow

1. Validate opportunity.yaml and experiment.yaml; match the exact fixture digest.
2. Freeze Twelve scripted agents, three assets, six rounds and four dated synthetic news events.
3. Run two candidates over seeds 17, 29 and 43 with two repetitions per seed.
4. Preserve Per-round bid ledgers, clearing prices, winning allocations, achieved/optimal value and counterfactual allocation changes.
5. Recompute descriptive statistics from all successful complete seed groups.
6. Verify evidence bytes before generating a self-contained review package.

## Reproducibility and limits

The run records code/input fingerprints, interpreter version, command, seed,
start/finish, elapsed time, return code and artifact digests. Computational replay
excludes timing and Python allocation peaks. All retained performance is a local
observation; requirement satisfaction needs separately scoped reviewed evidence.

A scripted auction is a mechanism baseline. It does not measure LLM-agent heterogeneity, persuasion effectiveness or a working influence classifier.

## Extension boundary

Add reviewed model-agent adapters, measured model latency/cost and behavioral hypotheses. Freeze a wider evaluation population and holdout protocol before testing interventions; obtain official topic and output constraints first.

No private runtime, live provider, credential, account, physical deployment or
external submission is created by this architecture.
