# Architecture — DIU Sentinel Maritime

Status: executable public reference workload, with measured trials generated by the shared runner.

## Purpose and implemented method

Reuse the existing public mission-suite analysis and proof path while measuring deterministic behavior before private Sentinel/NNC integration.

The reference calls the existing mission-suite engine twice: once with the frozen observation order and once with a seeded permutation. It compares the derived analysis rather than the input-bound proof, since permuted inputs legitimately have different input fingerprints. Candidates retain HOLD and no admission/release authority is granted.

obtain its own registered SRS/dispatch for subsequent lane implementation.

## Data and control flow

1. Validate opportunity.yaml and experiment.yaml; match the exact fixture digest.
2. Freeze Five explicit synthetic observations for three entities, including conflicting positions and a stale observation.
3. Run two candidates over seeds 17, 29 and 43 with two repetitions per seed.
4. Preserve Existing engine version/source identity, entity/world-state analysis, deterministic candidate results, proof fingerprints and HOLD/admission counts.
5. Recompute descriptive statistics from all successful complete seed groups.
6. Verify evidence bytes before generating a self-contained review package.

## Reproducibility and limits

The run records code/input fingerprints, interpreter version, command, seed,
start/finish, elapsed time, return code and artifact digests. Computational replay
excludes timing and Python allocation peaks. All retained performance is a local
observation; requirement satisfaction needs separately scoped reviewed evidence.

This is the already-present portable public engine. Its reference run does not establish private Sentinel deployment, live maritime detection quality, NNC integration or a 48-hour operating demonstration.

## Extension boundary

Follow the existing Sentinel ownership/discovery handoff and SM-BL-1.1 work orders. Receiving seats must verify actual private runtime, data rights, NNC admission and the operating demonstration against current DIU instructions.

No private runtime, live provider, credential, account, physical deployment or
external submission is created by this architecture.
