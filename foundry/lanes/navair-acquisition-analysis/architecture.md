# Architecture — NAVAIR Acquisition Analysis

Status: executable public reference workload, with measured trials generated by the shared runner.

## Purpose and implemented method

Provide deterministic retrieval with inspectable scoring, graded relevance and stable source citations before expanding to acquisition corpora.

The retrieval module tokenizes a frozen corpus with a Unicode word/case-fold rule. BM25 and cosine TF-IDF score the same queries and documents. Term contributions and source hashes accompany every hit; document IDs resolve equal scores. Recall and precision use explicit relevant/retrieved denominators, nDCG uses graded judgments, and MRR uses the full ranking.

## Data and control flow

1. Validate opportunity.yaml and experiment.yaml; match the exact fixture digest.
2. Freeze Nine authored public synthetic acquisition descriptions, six queries, graded judgments and top-k of three.
3. Run two candidates over seeds 17, 29 and 43 with two repetitions per seed.
4. Preserve Ranked hits with explanations and citations; precision@k, recall@k, nDCG@k and reciprocal rank for each query and the aggregate.
5. Recompute descriptive statistics from all successful complete seed groups.
6. Verify evidence bytes before generating a self-contained review package.

## Reproducibility and limits

The run records code/input fingerprints, interpreter version, command, seed,
start/finish, elapsed time, return code and artifact digests. Computational replay
excludes timing and Python allocation peaks. All retained performance is a local
observation; requirement satisfaction needs separately scoped reviewed evidence.

The current comparison is lexical retrieval over authored fixtures. It establishes no government-corpus accuracy, embedding quality, CUI suitability or tested container.

## Extension boundary

Acquire an explicitly releasable domain corpus, independent expert relevance judgments and a held-out query set. Add approved dense/hybrid retrieval baselines, then build and accept the required Docker deliverable on its declared runtime.

No private runtime, live provider, credential, account, physical deployment or
external submission is created by this architecture.
