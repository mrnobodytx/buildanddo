# Architecture — DAF NV027 Brain-Inspired Low-SWaP

Status: executable public reference workload, with measured trials generated by the shared runner.

## Purpose and implemented method

Measure the compute/accuracy tradeoff of conditional execution before investing in a trained heterogeneous architecture or edge device.

The simulation applies a fixed projection and leaky temporal state to labelled sequences. Dense execution projects every frame. Event-gated execution skips the projection when input activity is below the frozen gate threshold. Both use identical weights, states and tie rules; multiplication counts and the additional gate-feature checks are recorded separately.

## Data and control flow

1. Validate opportunity.yaml and experiment.yaml; match the exact fixture digest.
2. Freeze Four projection outputs over sixteen features and sixty-four labelled event/background frames.
3. Run two candidates over seeds 17, 29 and 43 with two repetitions per seed.
4. Preserve Frame predictions, label agreement, active/dense multiplication counts, active frames, gate-check counts and Python timing/allocation observations.
5. Recompute descriptive statistics from all successful complete seed groups.
6. Verify evidence bytes before generating a self-contained review package.

## Reproducibility and limits

The run records code/input fingerprints, interpreter version, command, seed,
start/finish, elapsed time, return code and artifact digests. Computational replay
excludes timing and Python allocation peaks. All retained performance is a local
observation; requirement satisfaction needs separately scoped reviewed evidence.

Fixed temporal projection is a simulation reference, not a trained neural design. Multiplication savings exclude decay/control overhead and do not establish energy, watts, VRAM or edge-device performance.

## Extension boundary

Register a trained brain-inspired architecture, real datasets, accuracy budgets and dense-model controls. Measure wall-clock latency and power on declared target hardware with an accepted instrumentation procedure after simulation evidence warrants it.

No private runtime, live provider, credential, account, physical deployment or
external submission is created by this architecture.
